## 二、核心实现研读

### 1. `src/features/attribution-index.ts` —— 引用归属索引（最重要的创新）

**原作者注释（原文）**：

```ts
/**
 * 归属索引 · 引用消息的发送者反查（M21）
 * ─────────────────────────────────────────────────────────────
 * 问题：QQ 合并转发（msgType=103）的 `msg_elements` **只有 content 字符串**，
 * 不含每条消息的发送者/nickname/timestamp。SDK 类型定义就是：
 *
 *     interface RawMsgElement { msg_idx?; content?; attachments? }
 *
 * 拿不到发送者 → 模型只能看到"某人" → 会瞎猜归属。
 * 真实事故（2026-10-31）：小羽把 jmx 说的「卡了就别催了」算成群主说的，
 * 回了句「刚不是你那边卡了」。
 *
 * 曾经用群历史缓冲反查，但 `clearGroupHistory` 每轮回复后都会清空它，
 * 导致反查永远命中不了。所以这里单独存一份**只用于反查**的小索引：
 *   - 与 historyBuffer 完全分离，不被清理
 *   - 不进模型上下文（只喂给 buildQuotePart 做归属判定）
 *   - 环形保存最近 N 条
 *   - **落盘持久化**：重启后仍能反查「重启前说过的话」
 *     （实测踩过：纯内存版重启清空，用户重启后再引用就认不出来）
 */
```

**这段注释的价值**：它记录了一条**完整的事故链**——不是"我设计了一个索引"，而是：

1. 现象：AI 把某人说的话算到别人头上
2. 根因：`msg_elements` 只有 content，没有 sender
3. 第一次尝试：用 `historyBuffer` 反查 → **失败**，因为 `clearGroupHistory` 每轮清空
4. 第二次尝试：独立索引 → **内存版失败**，重启就清空
5. 最终方案：独立索引 + 落盘持久化

**图片归属的妙招（原文注释）**：

```ts
  /**
   * 这条消息带的图片指纹（MD5）。
   *
   * 实测发现（2026-11-01）：QQ 下发的图片文件名本身就是**图片内容的 MD5**，
   * 与本地归档算出来的 md5 完全一致（逐字节核对过：
   *   4b859167d7bf796ef62ee84377c1224e  == 归档文件的实际 MD5）。
   * 所以"引用一张图是谁发的"可以直接用文件名对指纹，**不需要下载图片**，
   * 也不需要跑视觉模型 —— 事后 URL 会过期（实测返回 download url has expired）。
   */
  imageMd5?: string[];
```

**这个太实用了**：QQ 图片的**文件名就是内容 MD5**，所以判断"引用的这张图是谁发的"只要对文件名，**零下载、零视觉模型**。而且作者还注明了"事后 URL 会过期"这个坑。

**容量核算（原文注释）**：

```ts
/*
 * 存储量核算（放大到 100 条/群之后）：
 *   每群 100 × 200 字 ≈ 20 KB
 *   全局 200 群      ≈ 4 MB（理论上限）
 *   实测单群 100 条约 20 KB 落盘，完全可接受
 */
const MAX_PER_GROUP = 100;
const MAX_GROUPS = 200;
```

**落盘用原子替换**：

```ts
function persist(): void {
  const file = storePath();
  try {
    const dir = dirname(file);
    if (!existsSync(dir)) mkdirSync(dir, { recursive: true });
    const obj: Record<string, AttributionEntry[]> = {};
    for (const [k, v] of index) obj[k] = v.slice(-MAX_PER_GROUP);
    const tmp = `${file}.tmp`;
    writeFileSync(tmp, JSON.stringify(obj), 'utf8');
    renameSync(tmp, file);
  } catch {
    /* 落盘失败不影响内存查询 */
  }
}
```

（这里用的是固定 `.tmp` 名，和我们踩过的并发坑一样——单进程够用，多实例并发时会有问题。）

### 2. `src/persona/question-detect.ts` —— 中文口语疑问句识别（19KB，纯规则）

**原作者注释（原文）**：

```ts
/**
 * 中文口语疑问句识别 + 说话对象判定
 * ─────────────────────────────────────────────────────────────
 * 背景：QQ 群里大量提问不带问号、省略主语（"吃了吗""在干嘛""忙不忙"），
 * 靠 /[?？]|怎么|为什么/ 这种正则必然漏（实测 7 条全漏）。
 *
 * 做法：纯规则打分（无模型、无分词、无依赖），单条判定 < 0.05ms。
 * 依据：现代汉语四类疑问句（是非/特指/选择/正反）+ 吕叔湘《中国文法要略》
 * 的「疑·问」分离；工程实现参考 CCL2020《中文问句的形式分类和资源建设》
 * 与专利 CN107145514A 的特征集（语气词/疑问代词/正反格式/选择格式）。
 *
 * 关键设计：
 *  1. 不用「否定词+不」的固定串匹配，而是**逐位扫描**否定词两侧做反向比较，
 *     这样 忙不忙/来不来/困不困/行不行 全中，而 差不多/对不起/不得不 天然不中
 *     （两侧字不同）。这是识别正反问最省事又最准的写法。
 *  2. 每个信号给一个分数而非布尔，便于后续按场景调阈值；
 *     口语群里"吧"结尾的推测句、省略式"吃了没"这类高噪声情形单独降权。
 *  3. 只有"疑"没有"问"的句子要排除：我谁都不认识 / 没什么 / 不咋样。
 *  4. 单独提供「是不是在跟我说话」判定：第二人称、称呼、指名、以及
 *     上一轮是谁在对话（省略主语默认指向当前对话对象）。
 */
```

**最值得学的是第 1 点**：

> 不用「否定词+不」的固定串匹配，而是**逐位扫描**否定词两侧做反向比较，
> 这样 忙不忙/来不来/困不困/行不行 全中，而 差不多/对不起/不得不 天然不中（两侧字不同）。

这是一个**用结构代替枚举**的漂亮解法：汉语正反问句（V-不-V）的判定不需要维护一个词表，只要检查「否定词两侧的字是否相同」——相同就是正反问，不同就是普通词。**词表会漏，结构不会。**

而且它明确写了**实测数据**（"实测 7 条全漏"）、**学理依据**（吕叔湘 + CCL2020 论文 + 专利）、**性能指标**（< 0.05ms），这种注释质量很高。

### 3. `src/persona/wake.ts` —— 唤醒判定（19KB）

**原作者注释（原文）**：

```ts
/**
 * 唤醒判定 · 什么时候该说话，什么时候该安静
 * ─────────────────────────────────────────────────────────────
 * 移植自 ai-companion-kit（MIT）packages/companion/src/wake.js。
 *
 * 把"要不要醒"拆成独立条件，任一命中才醒：
 *   atMention / nameMention / keywords / question / speakerIds /
 *   probability / anyMessage
 * 注：原版的 poke（拍一拍）在 QQ 官方 Bot API 无对应事件，未移植。
 * 另含「无限期潜水」概念：醒过一次后，一段时间内除非再次命中否则装没看见。
 */
```

**按人计数的活跃窗口**：

```ts
/** 单个"提到过她的人"的活跃窗口与无关计数 */
export interface SpeakerWindow {
  /** 这个人的活跃窗口到期时间戳 */
  until: number;
  /** 这个人连续多少条"与她无关"的消息；到阈值就关掉**他自己**的窗口 */
  idleStreak: number;
  /** 这个人最后一次叫醒她的时间 */
  lastWakeAt: number;
}
```

**注意这个设计**：窗口是**按人**而不是按群。A 叫她一次，只有 A 的窗口打开；A 连续说了 3 条无关的话，只关 A 的窗口，不影响 B。这比"整个群进入活跃期"精确得多。

### 4. `src/persona/memory.ts` —— 按「人」存记忆，不按会话

**原作者注释（原文）**：

```ts
/**
 * 记忆账本 · 按「人」存，而不是按「会话」存
 * ─────────────────────────────────────────────────────────────
 * 移植自 ai-companion-kit（MIT）packages/companion/src/memory.js，
 * 作者 pinganbbOvO。逻辑保持一致，改为 TS 严格模式。
 *
 * 大多数聊天机器人把记忆按会话存：私聊一份、群聊一份、不同群各一份。
 * 结果就是同一个人换了地方，AI 就"不认识"他了。
 * 这里所有记忆都挂在人身上（官方 API 用 user openid 当 key）。
 */
```

**数据结构**：

```ts
export interface PersonLedger {
  name: string;
  traits: string[];      // 性格特征
  facts: string[];       // 事实
  topics: string[];      // 聊过的话题
  pending: string[];     // 记着还没说出口的事
  interactions: number;
  firstSeenAt: number;
  lastSeenAt: number;
}
```

**`pending` 这个字段很有意思**——"记着还没说出口的事"，这是给 AI 留的延迟表达空间。

### 5. `src/persona/own-life.ts` —— 「她自己的生活」定时静默唤醒

**原作者注释（原文）**：

```ts
/**
 * own-life · 「她自己的生活」定时静默唤醒
 * ─────────────────────────────────────────────────────────────
 * 移植自 ai-companion-kit（MIT）packages/own-life/src/own-life.js，
 * 适配 dsh-qqbot：deliver 不再是桥接的 deliverPrompt(silent)，
 * 而是向存活会话注入一条**静默 followup**（不进 QQ 聊天，只进 agent 上下文）。
 *
 * 设计约束（与原版一致）：
 * - 静默：提示只进 AI 的上下文，不往 QQ 发东西
 * - 不打扰：凌晨 quiet 时段不叫；一天最多 maxPerDay 次
 * - 可关：enabled=false 或 stop() 立刻停
 * - 断电续得上：最后触发时间写 statePath，重启不会一次补发一堆
 * - 投递失败不计次数（下次还会再试）
 */
```

**默认提示文本**（原文）：

```ts
export const DEFAULT_TEXT_DAY = [
  '现在是你的时间，没人找你。',
  '想干嘛干嘛：写条日记（qq_write_diary）、翻翻你记着还没说出口的事、',
  // ...
];
```

**设计亮点**：
- **静默**（只进上下文，不打扰用户）
- **限额**（一天最多 N 次，凌晨不叫）
- **断电续得上**（记 `statePath`，重启不补发）
- **失败不计次**（投递失败下次再试，不会因为一次失败就少一次机会）

## 四、对我们（`zaofan-make/dsh-qqbot`）的启示

这一支和我们的定位最接近（都是人设向），参考价值最大。

### 强烈建议借鉴的三点

**1. 引用归属必须独立于群历史缓冲**

我们现在的归属判定依赖 `historyBuffer`，而它每轮会被清空——**和作者踩的是同一个坑**。建议单独维护一个「只用于反查、不入上下文、环形 + 落盘」的小索引。

**2. 图片归属用文件名 MD5 对指纹**

零成本解决"这张引用的图是谁发的"。前提是 QQ 下发的文件名确实是内容 MD5（作者逐字节核对过）。

**3. `botSelfId` 接线 + 自己的话也进历史**

我们现在也会出现"认不出这是自己说的"吗？值得查一下。

### 值得学的设计思想

**「用结构代替枚举」** —— `question-detect` 里那个"逐位扫描否定词两侧做反向比较"，比维护词表优雅得多。我们做话题判断/唤醒判定时，可以借鉴这个思路。

**「按人计数而非按群」** —— `SpeakerWindow` 挂在人身上，比"整个群进入活跃期"精确。

**「记忆按人存而非按会话」** —— 我们的 `people_memo` 已经是对的（按人），这点没走弯路。

### 需要警惕的

**「指望模型自觉」是不可靠的** —— 作者那条提交说的很直白：*"记忆与日记改系统硬触发——「指望模型自觉写」实测等于不写"*。我们现在靠 `memory_log` 等工具，也需要确认**是不是真的每轮都在调**，而不是"设计上应该调"。

### 顺带一提

作者大量移植了 `ai-companion-kit`（MIT）这个项目（`wake.js` / `memory.js` / `own-life.js` / `question-detect` 的学理依据），而且是**明确署名原作者**（`作者 pinganbbOvO`）。这种交代来源的做法值得学习。
