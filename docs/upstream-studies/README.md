## 从这两份研读里落地的候选改进

以下按「性价比」排序，供后续排期参考（尚未实施）：

### 高优先

1. **引用归属独立索引**（参考 `495258544` 的 `attribution-index.ts`）
   我们现在的归属判定依赖`historyBuffer`，而它每轮被清空 —— 对方踩过完全相同的坑。
   建议：单独一份「只用于反查、不入上下文、环形 + 落盘」的小索引。

2. **图片归属用文件名 MD5 对指纹**
   零成本判断「引用的这张图是谁发的」。前提：QQ 下发的文件名确实是内容 MD5。

3. **`botSelfId` 接线 + 自己的话也进历史**
   否则 AI 认不出「这是你自己说的」，可能自己反驳自己。

### 中优先

4. **消息投递账本**（参考 `gosomea` 的 `delivery-ledger.ts`）
   我们发消息没有幂等保护，网络抖动重试可能重复发。
   哪怕只做「发送前记 key、成功标 accepted」也能挡掉大部分重复。

5. **wire 层统一拦截授权**（参考 `gosomea` 的 `qq-wire-admission.ts`）
   现在权限检查散在各调用点，`/tools-reload` 之类路径容易漏。

6. **`unknown` 投递状态**
   「不知道发没发出去」和「确定没发出去」在重试语义上完全不同，现在混在一起。

### 值得研究但工作量大

7. **中文口语疑问句识别**（`question-detect.ts`，19KB 纯规则）
   核心思路「逐位扫描否定词两侧做反向比较」很漂亮，但已是完整实现，可以直接借鉴其思路而非照搬。

8. **按人计数的活跃窗口**（`wake.ts` 的 `SpeakerWindow`）
   比「整个群进入活跃期」精确得多。

## 写作规范（给未来的自己）

写这类研读笔记时：

1. **必须署名**：原作者 + 原文地址 + 分支 + 整理时间 + 版权声明
2. **引用的代码要标注「原文」**，不要和我的解读混在一起
3. **保留原作者的实测数据**（「实测 7 条全漏」「逐字节核对过」这类）——那是笔记里最有价值的部分
4. **记录事故场景**（比如「小羽把 jmx 说的话算成群主头上」）——比抽象描述有用得多
5. **最后给出「对我们意味着什么」**，否则笔记就只是抄书
